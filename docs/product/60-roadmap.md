### M0-7 · F-8 판단 — **① 002를 멱등하게 고친다**

`migration-002.sql`의 `create table question_notes` · `create index …` · `create policy …` 둘 · `alter publication … add table` 다섯 문장에 **`if not exists`도 `drop … if exists`도 없다.** 002를 이미 돌린 프로젝트에 다시 붙여넣으면 첫 `create table`에서 멈춘다.

**저장소 소유자가 「D가 판단하게 둔다」고 했으므로 여기서 고른다. ①이다.**

| | ① 002를 고친다 | ② 007을 새로 만든다 |
| --- | --- | --- |
| 얻는 것 | 「여러 번 실행해도 같은 결과」 회복. 복구 절차가 한 줄 | 「기존 마이그레이션을 수정하지 않는다」 유지 |
| 잃는 것 | 그 전제를 한 번 깬다 | 복구 절차가 「002를 건너뛰고 007을 돌려라」가 된다 |

**왜 ①인가 — 넷.**

1. **저장소의 다른 SQL이 전부 이미 ①의 모양이다.** `schema.sql`은 `create table if not exists` 7회 · `create index if not exists` · `drop policy if exists` 19회 · 발행은 `do $$ … exception when duplicate_object then null; end $$`로 감쌌다. `migration-006.sql` 초안도 같다 — `if not exists` 13회 · `drop policy if exists` 9회 · 같은 발행 가드. **002 하나만 다르다.** ①은 002를 나머지와 같게 만들고, ②는 002를 「모두가 건너뛸 것을 기억해야 하는 유일한 파일」로 남긴다.

2. **이미 돌린 프로젝트에 ①은 위험하지 않다.** 바꾸는 것이 `create table` → `create table if not exists`, `create index` → `create index if not exists`, `create policy` 앞에 같은 이름의 `drop policy if exists`, 발행에 `duplicate_object` 가드다. **어느 열도 바뀌지 않고 어느 행도 움직이지 않는다.** 기존 표가 있으면 `if not exists`가 건너뛰고, 정책은 **글자 그대로 같은 정책이 다시 만들어진다** — `schema.sql`이 매 실행마다 이미 하고 있는 일이다.
   - **정직하게 적어 둘 두 가지.** ⓐ `drop policy` 뒤 `create policy` 사이의 짧은 순간 그 표에는 SELECT 정책이 없다. RLS가 켜진 표에 정책이 없으면 **막히지 열리지 않는다** — 실패 방향이 안전한 쪽이다. ⓑ `create table if not exists`는 **이미 어긋난 표를 고쳐 주지 않는다.** 누가 `question_notes`를 손으로 바꿔 뒀다면 ①은 그것을 조용히 지나간다. 그 경우는 F-1이 다룬 문제이고 그 처방은 ②쪽(새 파일에서 모양을 모은다)이다 — 아래 「전제를 어디까지 깨는지」 표.

3. **복구 절차를 읽는 사람이 새로 합류한 개발자다.** 이 저장소의 복구 절차는 「어디까지 적용됐는지 헷갈릴 때 처음부터 다시 붙여넣는다」이고, 그 사람은 이미 낯선 스키마를 세우는 중이다. ②의 절차는 **「schema.sql → 002는 건너뛰고 → 003 → 004 → 005 → 006 → 007」**이 된다. 중간에 예외가 있는 절차는 틀리게 실행된다. 틀리면 `question_notes`가 없고, 그러면 `/questions/:id`의 덧붙임이 **오류 없이 조용히 비어 있다.** ①의 절차는 한 줄이다 — **「`schema.sql`부터 번호 순서대로 전부 다시 붙여넣는다.」**

4. **②는 문제를 다 고치지 못한다.** 007을 만들어도 **002는 여전히 다시 붙여넣어지지 않는다.** 회복하는 것은 「원칙」이 아니라 「원칙을 피해 가는 길」이다.

**대신 전제를 어디까지 깨는지 못 박는다.** 「기존 마이그레이션을 수정하지 않는다」는 버리지 않는다. **모양을 바꾸지 않는 멱등화에만 예외를 준다.**

| 고치려는 것 | 어디서 |
| --- | --- |
| 멱등성만 더한다 (`if not exists` · `drop … if exists` · 발행 가드) | **기존 파일에서.** 결과가 같다 |
| 컬럼 타입·데이터·정책 의미가 바뀐다 | **새 파일에서.** F-1이 그 사례이고 006 §1이 옳게 그렇게 했다 |

**지금 SQL을 고치지 않았다.** 이 개정은 문서 작업이다. **M0-7의 실행은 코드 작업이며 M0-5와 같은 사람이 같은 순서로 한다** — 002를 고치고, 고친 002를 빈 프로젝트에 두 번 붙여넣어 같은 결과가 나오는지 확인하고, `40-data-model.md`의 F-8 줄을 닫는다.

**빈 라우트를 함께 넣는 이유** — 탭만 바꾸면 `진료` 탭이 없는 주소를 가리켜 **죽은 탭**이 된다. 껍데기와 리다이렉트까지가 한 몫이다.

**G-11이 여기 있는 이유는 같은 파일이다.** `/me/payment` 삭제는 `App.tsx`의 라우트를 지우는 일이고, 관문이 이미 `App.tsx`를 열어 둔다. **취향이 아니라 병목 때문에 여기다.**
