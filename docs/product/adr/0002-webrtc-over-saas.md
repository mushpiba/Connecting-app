# ADR 0002 · 화상은 SaaS 대신 WebRTC를 직접 든다

- 상태: **채택됨** (커밋 `cdef921`에서 결정, 여기 기록만 옮김)
- 날짜: 2026-08-19 기록 · 결정은 2026-08-12

## 맥락

1:1 화상 진료방이 필요했다. Daily 같은 화상 SaaS를 쓰는 선택지가 있었다.

## 결정

**Supabase Realtime 브로드캐스트로 시그널링하고, 미디어는 브라우저끼리 직접 흐르게 한다.**

## 근거

1. 계정을 하나 더 만들지 않아도 된다 — 이미 Supabase를 쓴다
2. **다음 단계에서 프레임을 직접 암호화하려면 어차피 `PeerConnection`을 우리가 들고 있어야 한다.** SaaS를 쓰면 그 시점에 갈아엎어야 한다

## 대가 (알고 받아들인 것)

- **중계 서버가 없어 대칭 NAT 뒤에서는 연결이 안 된다.** TURN을 붙여야 닫힌다 (`../50-nonfunctional.md` R-5)
- 시그널링 채널이 방 이름만으로 구독 가능하다 (R-3)
- 연결 안정성·재접속을 직접 다뤄야 한다

## 함께 정한 것

- **전사는 각자 자기 마이크만 받아 적어** 데이터 채널로 상대에게 보낸다. 상대 목소리를 내가 받아 적으면 마이크 품질에 따라 엉뚱한 말이 기록으로 남는다
- **키워드는 사연 분류와 같은 규칙셋을 쓴다.** 통화용 규칙을 따로 만들면 두 곳의 기준이 갈라지고 어느 쪽이 맞는지 아무도 모르게 된다
- **키워드와 기록 초안은 의사에게만 보인다.** 환자 화면에 키워드를 띄우면 진단으로 읽힌다
- 브라우저 내장 음성인식은 음성을 제조사 서버로 보내므로 **실제 환자 대화에는 쓸 수 없다** (R-4). 교체 지점을 훅 하나(`useSpeechTranscript.ts`)로 모아 뒀다
