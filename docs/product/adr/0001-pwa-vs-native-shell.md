# ADR 0001 · PWA를 유지한다. 네이티브 쉘은 트리거가 왔을 때 결정한다

- 상태: **결정됨 — Capacitor 쉘. 실행은 M3** (2026-08-27 재검토)
- 날짜: 2026-08-19 · **재검토 2026-08-27** — 아래 §2026-08-27 재검토

> 아래 본문은 2026-08-19판 그대로다. **고치지 않는다** — 그때 무엇을 근거로 보류했는지가 재검토의 입력이다.

## 맥락

설치형 PWA로 써 본 사람에게서 "앱 특유의 조작감이 없다"는 지적이 나왔다. 네이티브나 Capacitor 같은 다른 방식으로 만들었어야 하는 것 아니냐는 제안이 함께 있었다.

원인을 코드에서 추적했다. 지적된 체감 8가지 중 **7가지가 웹 레이어에서 해결되는 것**이었다.

| 체감 | 실제 원인 | 플랫폼 한계인가 |
| --- | --- | --- |
| 터치 반응이 밋밋 | `:active`가 `translateY(1px)`뿐, `-webkit-tap-highlight-color` 0회 | 아니오 |
| 애니메이션 없음 | `@keyframes` **0개 / 3,850줄** | 아니오 |
| 로딩이 허전 | 스켈레톤·스피너 0개 | 아니오 |
| 화면 전환이 끊김 | 라우트 전환 없음 | 아니오 (View Transitions API) |
| 하단바가 제스처바에 먹힘 | `viewport-fit=cover`가 없어 safe-area 7규칙이 죽어 있음 | 아니오 |
| 탭 누를 때 글자가 덜컹 | 활성 탭 `font-weight` 변경으로 리플로우 | 아니오 |
| 스크롤이 브라우저 같음 | `overscroll-behavior`가 데스크톱 전용 미디어쿼리 안 | 아니오 |
| 햅틱 없음 | `navigator.vibrate` 0회 | **부분적** — Android 가능, iOS 불가 |

상세는 `../50-nonfunctional.md`의 조작감 백로그 23개 항목.

## 결정

**지금은 PWA를 유지하고 웹 레이어를 채운다.** Capacitor / React Native 도입은 결정하지 않는다.

## 근거

1. **원인이 아닌 곳을 고치게 된다.** 조작감 백로그 23개 중 네이티브가 필요한 것은 햅틱(I-19) 하나다. 쉘을 씌워도 `@keyframes` 0개는 그대로다.
2. **Capacitor는 나중에 씌울 수 있다.** 같은 웹 코드를 유지한 채 감싸는 방식이라 지금 결정해서 얻는 것이 없다. 반대로 React Native / Flutter 재작성은 15,358줄과 257개 테스트, GitHub Pages 배포 파이프라인을 대부분 버린다.
3. **지금 팀에 네이티브 빌드·서명·심사를 감당할 여력이 없다.** 개발자 2~3명이 합류하는 시점에 새 빌드 파이프라인을 얹으면 M1이 통째로 밀린다.
4. **비용 대비 효과가 압도적으로 다르다.** P0 10개는 CSS와 메타 태그 수정이고, 그중 하나(`viewport-fit=cover` 한 줄)가 이미 작성된 safe-area 규칙 7개를 되살린다.

## 언제 다시 결정하는가 — 트리거

아래 중 **하나라도** 참이 되면 이 ADR을 다시 연다.

- **푸시 알림이 필수 요구사항이 된다.** "답변이 도착했다"를 안 보고 있을 때 알려야 하는 순간. iOS PWA 푸시는 홈화면 설치 + iOS 16.4+ 조건부이고 백그라운드 제약이 있다
- **앱스토어 배포가 사업 요구가 된다.** 비대면진료 제품에서 스토어 존재는 유통 채널이자 신뢰 신호다. 의원이 환자에게 배포할 때 "앱스토어에서 받으세요"가 필요해지는 시점
- **iOS 사용자가 실제 대상이 된다.** 현재는 Android Chrome PWA를 1순위로 두고 iOS는 설치 안내도 없다
- **통화 중 백그라운드 유지나 수신 화면이 필요해진다.** 화면을 나가면 통화가 끊기는 것이 파일럿에서 문제가 되는 순간

## 다시 열었을 때 비교할 것

| | PWA 유지 | Capacitor 쉘 | 네이티브 재작성 |
| --- | --- | --- | --- |
| 기존 코드 | 그대로 | 그대로 | 대부분 폐기 |
| 햅틱 (iOS) | 불가 | 가능 | 가능 |
| 푸시 (iOS) | 제한적 | 가능 | 가능 |
| 스토어 배포 | 불가 | 가능 | 가능 |
| 빌드·심사 부담 | 없음 | 중간 | 큼 |
| 조작감 | **백로그 22/23 해결 가능** | 동일 + 햅틱 | 최상 |

**세 안 모두 조작감 백로그를 먼저 해결해야 한다.** Capacitor를 골라도 CSS는 그대로 쓰인다. 그래서 지금 P0을 하는 것은 어느 미래에서도 낭비가 아니다.

## 결과

- `../50-nonfunctional.md`의 I-1 ~ I-23이 실행 항목이 된다
- `../60-roadmap.md` M1-B에 I-1 ~ I-10이 배치된다
- 이 ADR은 위 트리거 중 하나가 참이 될 때까지 열지 않는다

# 2026-08-27 재검토

## 왜 열었나

**트리거 넷 중 셋이 참이 됐다** — 푸시 알림 필수 · 앱스토어 배포 필요 · iOS 사용자가 실제 대상. 저장소 소유자가 확인했다.

함께 나온 요구가 하나 더 있다: **"실시간으로 확인하면서 진행하고 싶다."** 이건 트리거가 아니라 개발 방식에 대한 요구인데, **선택지를 가르는 데 결정적이다.**

## 결정 — Capacitor 쉘. Flutter/React Native 재작성은 하지 않는다

| | PWA 유지 | **Capacitor** | 네이티브 재작성 |
| --- | --- | --- | --- |
| 켜진 트리거 3개 | ✗ | **✓ 셋 다** | ✓ 셋 다 |
| 기존 코드 17,382줄 | 그대로 | **그대로** | 대부분 폐기 |
| 257개 테스트 · `ci.yml` | 그대로 | **그대로** | 다시 씀 |
| 브라우저로 확인하는 개발 루프 | 유지 | **유지** | **끊김** |
| 빌드·서명·심사 부담 | 없음 | 중간 | 큼 |

**PWA 유지는 더 이상 답이 아니다** — 트리거 셋을 하나도 못 덮는다. 그러나 그 셋을 덮는 데 재작성이 필요하지 않다. **Capacitor가 같은 웹 코드를 그대로 감싸서 셋을 전부 준다.**

재작성을 기각하는 이유는 08-19판 §근거 2와 같고, 여기에 하나가 더 붙는다 — **네이티브로 가면 개발 중 실시간 확인이 끊긴다.** 브라우저는 열어서 볼 수 있지만 에뮬레이터는 그렇지 않다. 요구된 개발 방식 자체가 웹 레이어를 가리킨다.

## 실행 시점 — 지금이 아니라 M3

**지금 얹지 않는다.** 이유 셋.

1. **어느 안을 골라도 조작감 백로그가 먼저다.** 08-19판 §근거 4 그대로다. Capacitor를 씌워도 `@keyframes` 0개는 그대로고, 23개 중 22개는 CSS다.
2. **M1이 밀린다.** 개발자가 합류하는 시점에 빌드·서명·심사 파이프라인을 함께 얹으면 M1-0 관문부터 늦어진다.
3. **트리거는 전부 배포에 관한 것이다.** 푸시·스토어·iOS 셋 다 사람이 실제로 쓰기 시작할 때 필요하고, 그 시점이 M3(파일럿 직전)다.

`../60-roadmap.md` M3에 배치한다.

## 이 결정이 만드는 새 제약

Capacitor WebView에서 지금 코드가 그대로 도는지 확인했다.

| API | 어디 | 판정 |
| --- | --- | --- |
| `HashRouter` | `App.tsx:166` | **문제없음.** 서버 라우팅이 필요 없어 오히려 유리하다 |
| `RTCPeerConnection` · `getUserMedia` | `useConsultRoom.ts:95` `:104` | **문제없음.** 권한 설정(`Info.plist` · `AndroidManifest`)이 필요하다 |
| `SpeechRecognition` / `webkitSpeechRecognition` | `useSpeechTranscript.ts:29` | **iOS WKWebView에 없다** |

**세 번째가 R-4를 백로그에서 차단 항목으로 올린다.** `../50-nonfunctional.md`의 R-4는 「브라우저 내장 음성인식 → 기기 내 모델」을 *실제 환자 대화 전*에 닫을 항목으로 두고 있었다. iOS 쉘을 씌우면 **그 전에 이미 동작하지 않는다** — 실시간 전사가 조용히 비어 있는 채로 나간다.

다행히 코드는 이미 없을 때를 처리한다(커밋 `c6baaf7` — 왜 조용한지 보여 주고 타이핑으로 대체). **그러나 「받아쓰기가 안 되는 것」이 iOS에서는 예외가 아니라 기본값이 된다.** R-4와 Capacitor 도입은 **같은 마일스톤에서 같이 간다.**
