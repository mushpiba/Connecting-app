## 1. 원칙

### IA-1 · 두 진입로를 섞지 않는다

환자는 두 상태 중 하나로 앱을 연다. **상태가 다르면 필요한 화면이 다르다.**

| | 의사 찾기 | 주변·재진 |
| --- | --- | --- |
| 환자 상태 | 볼 의사를 **모른다** | 볼 의사를 **안다** |
| 하는 일 | 사연을 쓰고, 모인 답변에서 스스로 고른다 | 지도나 진료 이력에서 바로 예약·비대면 신청 |
| 걸리는 시간 | 답변을 기다린다 (비동기) | 즉시 |
| 홈 기본값 | **예** (D-5) | 아니오 — 별도 탭 |

한 화면에서 둘을 다 처리하려 하면 둘 다 흐려진다.

### IA-2 · 아픈 사람의 불안을 줄이는 정보는 늘린다

`05-decisions.md` P-1. 입력 칸·결정 횟수는 줄이되, **진행 상태·근거·다음에 일어날 일은 늘린다.** 힉의 법칙을 이 도메인에 그대로 적용하지 않는다.

구체적으로 — **내 요청이 지금 어디까지 왔는지는 어느 화면에서든 두 번 안에 닿아야 한다.**

### IA-3 · 플랫폼이 의사를 고르는 자리를 만들지 않는다

C-2. 의사 목록의 기본값은 **전체 목록 + 중립 필터**(진료과·거리·예약 가능 여부)다. "추천", "당신에게 맞는", "인기" 같은 묶음은 IA에 존재하지 않는다. 없는 화면은 실수로 만들어질 수 없다.

키워드 매칭은 **사연 → 의사 인박스** 방향으로만 흐른다. 그 반대 방향(환자에게 의사를 골라 주는)은 만들지 않는다.

### IA-4 · 두 정체성은 트리를 공유하지 않는다

같은 계정이 환자로도 의사로도 참여한다. `/`와 `/doctor/`는 **별개의 트리**이며 탭도 따로 갖는다. 섞이면 환자가 누구에게 묻는지 잘못 판단한다.

## 2. 최상위 구조 — 탭 재편 **[채택 · 2026-08-27]**

D-5로 홈의 기본이 사연 피드가 되면서 **기존 `홈`과 `사연` 탭이 같은 것을 가리키게 됐다.** 그대로 둘 수 없다.

### 환자 탭

| # | 탭 | 라우트 | 담당 | 현재와 비교 |
| --- | --- | --- | --- | --- |
| 1 | **홈** | `/home` | 사연 피드 (의사 찾기) + 진행 상태 스트립 | **역할 변경** — 대시보드 → 피드 |
| 2 | **내 소식** | `/news` | 내 사연과 도착한 답변 | **탭으로 승격** — 현재는 헤더 종 아이콘 |
| 3 | **Q** | `/ask` | 사연 작성 (중앙 버튼) | 유지 |
| 4 | **진료** | `/care` | 지도 + 내가 진료봤던 곳 + 예정된 예약·진료방 | **신설** — 현재 `/map` 확장 |
| 5 | **MY** | `/me` | 설정 | 유지 |

**없어지는 것:** `사연` 탭 (홈이 그 역할을 가져감).

### 왜 이렇게 바꾸나

- **`내 소식`을 탭으로 올리는 이유** — 무료 커뮤니티에서 재방문의 이유는 하나다. **내 사연에 답이 달렸는가.** 그 보상을 헤더 종 아이콘에 두면 앱의 심장이 부속으로 밀린다. D-1이 Q&A를 축으로 정한 이상 여기는 탭이어야 한다.
- **`지도`를 `진료`로 넓히는 이유** — IA-1의 두 번째 진입로 전체가 여기 들어간다. 지도(주변)와 진료 이력(재진)은 **"볼 의사를 아는 환자"라는 같은 상태**를 다룬다. 별개 탭 두 개로 쪼개면 5개 자리에 안 들어가고, 사용자에게도 같은 일이 두 곳에 있는 것처럼 보인다.
- **`홈`이 대시보드를 잃는 대신** — 진행 상태 스트립이 그 역할을 이어받는다. 아래 참조.

### 진행 상태 스트립

D-5의 비용(갈 곳을 아는 환자에게 한 단계가 늘어남)을 홈을 상태별로 바꾸지 않고 푸는 장치다. **홈이 사람마다 다르면 설명도 테스트도 어려워진다.**

- 위치: `/home` 사연 피드 **위**, 고정
- 조건: 진행 중인 건이 있을 때만 나타난다. 없으면 자리도 차지하지 않는다
- 내용: `답변 도착 n건` · `예약 예정` · `진료방 열림` 중 **가장 급한 하나**
- 동작: 누르면 해당 화면으로 직행
- 근거: IA-2. 아픈 사람이 자기 요청의 생사를 확인하는 최단 경로

`encounterTrack`의 4단계 추적이 이미 이 데이터를 만든다. 새로 계산할 것이 없다.

### 의사 탭 — 변경 없음

| # | 탭 | 라우트 | 담당 |
| --- | --- | --- | --- |
| 1 | 홈 | `/doctor/home` | 오늘 할 일 요약 |
| 2 | **받은 질문** | `/doctor/inbox` | 내 과·내 키워드에 걸린 사연. **의사 앱의 중심** |
| 3 | 사연 | `/doctor/stories` | 전체 피드 |
| 4 | 진료 | `/doctor/visits` | 예약·비대면 일정 |
| 5 | MY | `/doctor/me` | 프로필·키워드·비대면 설정 |

D-1이 Q&A를 축으로 정했으므로 **`받은 질문`이 의사 앱의 중심**이다. 하루 답변 상한 **5회**(D-8)의 잔여 횟수와 초기화 시점을 이 화면 상단에 상시 노출한다 — 상한은 감추는 제약이 아니라 **드러내는 자원**이다. 언제 다시 채워지는지 모르면 희소성이 아니라 그냥 막힘이다.

## 3. 화면 지도

`신설` = 화면이 없음 · `변경` = 있으나 역할이 달라짐 · `유지` = 그대로

### 환자

```
/onboarding                        게이트 · 유지
│
├─ /home                           홈 = 사연 피드           변경
│  ├─ [진행 상태 스트립]                                     신설
│  └─ /questions/:questionId       사연 상세                유지
│     ├─ 답변 목록 (전체, 정렬 공개)
│     ├─ 비공개 덧붙임              D-6 · 구조 강제 6항목     신설
│     └─ /doctors/:doctorId        의사 프로필              변경 (C-3)
│
├─ /news                           내 소식 = 내 사연과 답변  변경 (탭 승격)
│
├─ /ask                            사연 작성 3단계          유지
│
├─ /care                           진료 (주변 · 재진)       신설
│  ├─ 지도 (← 현재 /map)           주변 의원               변경
│  ├─ 내가 진료봤던 곳              재진 · 두 출처           신설
│  │  ├─ 앱 내 이력 (자동)          bookings · encounters
│  │  └─ 환자 직접 등록 (수동)      검증 안 됨 · 등급 구분
│  ├─ 예정된 예약·진료방            ← /me/appointments 흡수
│  ├─ /booking/:doctorId           대면 예약 3단계          유지
│  ├─ /me/precheck                 비대면 사전 확인         유지
│  └─ /visit/:roomId               화상 진료방              유지
│
└─ /me                             MY                     유지
   └─ /me/address /payment /notifications /privacy
```

**리다이렉트로 남기는 것:** `/map` → `/care` · `/stories` → `/home` · `/me/appointments` → `/care`.
셋 다 흡수됐지만 기존 링크와 북마크가 살아 있어야 한다.

### 재진의 두 출처 (Q-4)

| 출처 | 어디서 오나 | 신뢰 등급 |
| --- | --- | --- |
| **앱 내 이력** | `bookings` · `encounters` 조회. 자동 | 검증됨 — `clinics`를 가리킨다 |
| **환자 직접 등록** | 환자가 "여기 다니고 있어요"를 손으로 추가 | **검증 안 됨** — 화면에서 구분해 표시한다 |

앱 내 이력만 두면 신규 사용자의 재진 섹션이 영원히 비어 있고, IA-1의 두 번째 진입로가 처음부터 죽는다. 그래서 직접 등록을 연다. **대신 두 출처를 섞어 보여 주지 않는다** — 검증되지 않은 데이터가 검증된 것처럼 보이면 안 된다.

**추후 확장 (지금 만들지 않음):** 의료기관 연계를 통한 "불러오기". 자리만 남기고 화면은 만들지 않는다.

### 의사

```
/doctor/home                       홈                      유지
├─ /doctor/inbox                   받은 질문 + 잔여 답변 횟수  변경
│  └─ /doctor/questions/:id        답변 작성                유지
├─ /doctor/stories                 사연 피드                유지
├─ /doctor/visits                  진료                    유지
│  └─ /doctor/visit/:roomId        화상 진료방              유지
└─ /doctor/me                      MY                      유지
   └─ /doctor/me/profile /keywords /telemedicine
```

## 4. 이동 규칙

### 셸이 사라지는 화면

헤더와 하단 탭을 **숨기는** 화면은 "지금 이것만 하는" 화면이다. 여기서 나가려면 명시적으로 나가야 한다.

| 화면 | 왜 숨기나 |
| --- | --- |
| `/onboarding` · `/expert` | 게이트. 통과 전에는 다른 곳이 없다 |
| `/ask` | 3단계 작성. 중간 이탈이 곧 미완성 사연이다 |
| `/visit/:roomId` · `/doctor/visit/:roomId` | 통화 중. 실수로 나가면 상대가 혼자 남는다 |
| `/me/precheck` · MY 설정 5종 | 한 화면 한 목적 |

### 뒤로 가기

- 탭 사이 이동은 히스토리를 쌓지 않는다
- 3단계 작성(`/ask`, `/booking`)의 뒤로 가기는 **단계 뒤로**이며, 1단계에서의 뒤로 가기는 이탈 확인을 받는다
- 진료방에서의 뒤로 가기는 **나가기 확인**을 받는다

### 모달·바텀시트를 쓰는 자리

되돌릴 수 없는 동작의 확인, 그리고 **본문 흐름을 끊지 않아야 하는 보조 정보**에만 쓴다. 모달 안에 새 결정을 만들지 않는다 — 모달은 라우트가 없어서 뒤로 가기가 안 통한다.

## 5. 두지 않는 것

C-2와 IA-3의 결과다. **이 목록은 취향이 아니라 규제다.** 추가하려면 `05-decisions.md`를 먼저 고쳐야 한다.

| 두지 않는 것 | 이유 |
| --- | --- |
| "추천 의사" · "당신에게 맞는 의사" · "인기 의사" 섹션 | 제34조의9 선택 유도 |
| 답변 품질·평점 기반 의사 랭킹 화면 | 〃 |
| 의사 프로필의 평점·후기·전후사진·가격·홈페이지 링크 | C-3 (제57조3항 심의 예외 이탈) |
| 답변 본문 안의 예약 버튼 | 답변과 예약은 시각적·기능적으로 분리 |
| 결제·구독·상단 노출 구매 화면 | D-4 |
| 약 배송 화면 | 범위 밖 (약사법) |
| 진단명·질병 확률·중증도 지수 | C-5 |
| 의원 운영자용 화면 | D-1로 범위 밖. P3은 대상 아님 |

**답변 본문과 예약의 관계** — 사연 상세에서 답변을 읽고 그 의사에게 가려면 `의사 프로필`을 한 번 거친다. 이 한 단계는 마찰이 아니라 **분리의 증거**다. 없애지 않는다.
