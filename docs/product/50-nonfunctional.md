## 의료 안전 경계

`00-product-definition.md`의 원칙과 `05-decisions.md`의 제약 중 **코드가 실제로 지키는 것들**이다. **이 경계를 넘는 PR은 반려한다.**

원칙은 우리가 정한 것이라 우리가 바꿀 수 있다. **제약(C-*)은 우리가 정한 것이 아니라 바꿀 수 없다.** 아래를 두 표로 나눠 두는 이유가 그것이다.

### 임상 경계 — 진단하지 않는다

| 경계 | 어디서 지키는가 |
| --- | --- |
| 진단명·질병 확률·중증도 지수를 만들지 않는다 (**C-5**) | `triage`가 진료과 후보까지만 반환. Edge Function은 10개 진료과 enum으로 제한 |
| 응급 판정은 규칙이 한다 | `triageRules`의 `RedFlagRule`. 모델 경로를 타지 않는다 |
| 근거는 환자가 쓴 말만 | 함수에서 한 번, 화면에서 한 번 이중 필터 |
| 답변 문구에 진단명 없음 | `answerTemplates` |
| EMR로 넘기는 것은 환자 말 + 키워드 + 의사 문장 | `emrExport` |
| 통증 척도로 판정하지 않음 | 저장만 하고 어떤 함수도 읽지 않는다 |
| 응급 신호가 걸리면 119 안내를 먼저 | `/ask` 결과 화면 |

**척도는 출판된 설명이 있는 것만 쓴다** (NRS · mMRC · Bristol). PHQ-9 / GAD-7 같은 선별 도구는 넣지 않는다 — 넣는 순간 이 앱이 선별 도구가 된다.

### 법적 제약 — C-1 ~ C-5

근거 법령과 판례는 `05-decisions.md`에 있다. 여기는 **코드의 어디가 그것을 지키는지**만 적는다.

| ID | 제약 | 코드의 어디가 지키는가 |
| --- | --- | --- |
| **C-1** | 진료 성사에 연동된 대가를 받지 않는다 | 결제·정산·수수료 코드가 없다. `/me/payment`는 마스킹된 데모 값만 보여 준다. D-4가 결제 화면 자체를 만들지 않기로 했다 |
| **C-2** | 특정 의료기관·의료인 **선택을 유도하지 않는다** — 대가 여부와 무관 | 매칭은 `doctorFeed`의 **사연 → 의사 인박스** 한 방향뿐이고, `FeedReason`이 왜 걸렸는지 밝힌다. 정렬은 응급 우선 하나 외에 없다. 예약 버튼은 `DoctorProfileScreen`에만 있고 `QuestionDetailScreen`에는 없다 — 답변과 예약이 분리돼 있다 |
| **C-3** | 의사 프로필 필드는 제57조3항 심의 예외 항목으로만 구성한다 | **아직 다 지키지 못한다.** 평점·후기·전후사진·가격·홈페이지 링크는 코드에 없다. 그러나 `Doctor`의 `bio`·`consultStyle`·`career`는 심의 예외 목록 밖이고, 답변 본문의 병원명 필터와 그 로그도 없다 |
| **C-4** | 진료기록의 작성 주체는 의료인이다 | `emrExport`의 `recordDraft`는 의사가 쓴 답변 본문 그대로다. 전사에서 만든 것은 초안이고 의사가 고쳐 쓰는 출발점이다 |
| **C-5** | 진단명·질병 확률·중증도 지수를 출력하지 않는다 | 위 임상 경계 표 전체 |

**C-2를 지키는 것 중 아직 없는 것이 하나 있다** — 하루 답변 수 상한. **숫자는 정해졌다(5회/일, `05-decisions.md` D-8). 코드에 없을 뿐이다.** 잔여 횟수와 초기화 시점을 `/doctor/inbox` 상단에 상시 노출하는 것까지가 요구사항이며, 값은 `src/data/rules/*`에 `asOf`와 함께 둔다.

**C-3은 코드가 따라가야 할 항목이다.** 프로필 필드 정리와 병원명 필터·필터링 로그는 `30-feature-spec.md`·`40-data-model.md` 개정에서 다룬다.

### 위험 수용 항목 (지금 알고도 두는 것)

| # | 무엇 | 왜 지금은 두는가 | 언제 닫는가 |
| --- | --- | --- | --- |
| R-1 | **anon key가 번들에 하드코딩** (`src/data/supabaseClient.ts`) | RLS가 실제 게이트이고 service_role은 없다 | 실제 사용자 데이터가 들어가기 전 |
| R-2 | **면허 검증을 화면에서 스스로 켤 수 있다** (migration-004) | 모여서 테스트할 때 매번 SQL로 승격시키면 진행이 끊긴다 | **실서비스 전환 시 가장 먼저** |
| R-3 | **시그널링 채널이 방 이름만으로 구독 가능** | 단기 토큰 발급이 필요하고 그건 서버가 필요한 일 | 실제 진료 전 |
| R-4 | **브라우저 내장 음성인식** — 음성이 브라우저 제조사 서버로 간다 | 데모에 자체 모델을 붙일 수 없다 | **실제 환자 대화 전.** 기기 내 모델이어야 종단간 암호화가 성립 |

R-2 · R-3 · R-4는 **실제 환자를 태우기 전에 반드시 닫아야 하는 것들**이다. R-1 · R-5는 그 다음이다.

### 동의

화면에 적은 것과 실제로 일어나는 일이 **같아야 한다.** 서버로 보내면서 브라우저에만 둔다고 적는 것은 문구 오류가 아니라 동의를 잘못 받은 것이다. 증상 글이 모델 제공자에게 간다는 사실은 작성 화면에 적는다 — 구현 세부가 아니라 동의 사항이다.

## 앱 조작감 — 백로그

**배경.** 설치형 PWA로 써 보면 "앱 같지 않다"는 지적이 나온다. 원인을 추적한 결과 **플랫폼 한계가 아니라 아직 안 쓴 CSS**였다. `src/styles.css`에 `@keyframes`가 **0개**다. 앱 전체에서 스스로 움직이는 것이 하나도 없다.

기반은 이미 깔려 있다 — 모션 토큰(`styles.css:39-40`), tappable 전역 transition(`:88`), `@media (hover: hover)` 게이팅(`:104`), `prefers-reduced-motion` 리셋(`:2785`), 44px 터치 타깃(`:2794`). **표현만 비어 있다.**

### P0 — 저위험, 즉시 체감

| # | 항목 | 근거 |
| --- | --- | --- |
| I-1 | `index.html:5`에 `viewport-fit=cover` 추가 | **없어서 `env(safe-area-inset-*)` 7곳이 전부 `0px`로 죽어 있다** (`:186` `:282` `:345` `:346` `:3215` `:3378` `:3497`). 하단 내비가 제스처바에, 헤더가 상태바에 먹힌다 |

| I-3 | `background_color` 통일 | `vite.config.ts:18` `#edf2f6` vs `body` `#eef1f1`. 스플래시→앱 전환에서 색이 튄다 |

## 접근성

**있는 것** — `:focus-visible` 3px 아웃라인(`:74`) · 44px 최소 터치 타깃(`:2794`) · `prefers-reduced-motion` 전역 리셋(`:2785`) · 네이티브 `<details>` · `accent-color`

**없는 것**

- `aria-busy` 0회 — 로딩 상태를 스크린리더가 모른다
- 포커스 트랩 없음 (모달이 없어서 아직 필요 없지만 I-20과 함께 필요)
- `DoctorInboxScreen.tsx:99`의 클릭 가능한 `<div>` (I-18)
- 라우트 변경 시 포커스 이동/알림 없음

## 성능

- 런타임 의존성 4개뿐: `react` `react-dom` `react-router-dom` `@supabase/supabase-js`. **애니메이션 라이브러리 없음** — 위 백로그는 전부 CSS와 플랫폼 API로 해결한다. framer-motion을 들이지 말 것
- Realtime 핸들러가 **스냅샷 전체를 다시 읽는다** (`liveRepository.ts:259`). 이 규모에서는 의도된 단순함이지만, 사연이 수천 건이 되면 바꿔야 한다
- 분류기 4초 타임아웃 — 분류가 늦다고 사연을 못 올리게 두지 않는다
