## 왜 세션을 나누나

문서 4종을 한 세션에서 연달아 쓰면 뒤 문서가 앞 문서의 결정을 미묘하게 배반한다. 바이브 코딩의 기준점으로 쓸 문서에서는 **정합성이 분량보다 중요하다.** 그래서 문서마다 새 세션에서 쓰고, 매 세션은 `05-decisions.md`를 입력으로 받는다.

## 순서 — 지킬 것

```
[완료] 05-decisions.md                   결정과 제약
[완료] 15-information-architecture.md    IA
[완료] 미결 닫기                          Q-1~Q-4 · D-6 · D-8 · D-2
[완료] A. PRD 갱신                        00 · 10 · 20 · 50
[완료] B. 화면 설계서                     30-feature-spec (140KB, G-1~G-10)
[완료] C. 데이터베이스 설계서              40-data-model + migration-006 (F-1~F-5 닫힘)
   │
   ├─ D. 로드맵 갱신과 역류 반영   ← 실행 가능
   │
   └─ _bive 파생본                ← D가 끝난 뒤 (D-7)
```

**왜 D가 필요한가** — B와 C가 구현 항목 스물일곱 개(G-1~G-10 · F-7~F-9 · R-6~R-7 · Q-7~Q-9)를 새로 찾았는데, 그것들이 발견된 문서 안에만 있다. **일정과 분담을 정하는 `60-roadmap.md`는 아직 그 존재를 모르고, D-1이 열려 있던 시절의 문장을 갖고 있다.**

A와 B는 서로 다른 파일을 만져서 순서가 없었다. C는 B에 의존했다 — **화면이 무엇을 요구하는지 모르는 상태에서 스키마를 고치면 안 쓰이는 컬럼이 또 생긴다.** `40-data-model.md`의 F-2가 정확히 그렇게 생겼다.

## 혼자 만든다 (2026-08-27 변경)

D-7의 「나 + 개발자 2~3명」은 **「나 혼자 만들고 최종 검토만 남에게 맡긴다」**로 바뀌었다. 그래서 —

- **M0-3(`styles.css` 소유자 지정)은 없어졌다.** 동시에 손댈 사람이 없다
- **M0-4는 충돌 방지가 아니라 검토 가능성이 목적이다.** 커밋을 검토자가 읽을 수 있는 크기로 자른다
- **의존성은 그대로다.** 병렬이 사라져도 순서는 사라지지 않는다

## _bive 파생본 — 마지막에

D-7의 결정이다. **위 문서를 전부 만든 뒤에** 바이브 코딩 전용본을 `_bive` 접미사로 따로 만든다.

- 원본을 고치지 않는다. 파생본이 원본을 대체하지 않는다
- 배경 설명·근거·보고서 인용을 걷어내고 **제약·금지·판정 기준만** 남긴다
- 원본이 바뀌면 파생본을 다시 만든다. 파생본을 손으로 고쳐 원본과 어긋나게 두지 않는다
