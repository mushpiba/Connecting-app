## 반드시 지킬 것

### G-10 · 상태 전이

의사 화면에 **확인 / 거절 / 진료 마침**을 더한다. `DoctorVisitsScreen.tsx:98`이 `in-progress` 하나만 안다.

`20-user-flows.md`의 상태 전이도가 정본이다. **거기 없는 상태를 만들지 마라.** `src/domain/encounterTrack.ts`는 순수 함수이므로 **기준일을 인자로 받는다** — 무인자 `Date.now()`를 쓰지 마라(원칙 8).

### G-6 · 답변 상한

**값은 5회/일**(D-8). `src/data/rules/`에 `asOf`와 함께 새 파일로 둔다. **판정 코드에 상수로 박지 마라**(원칙 7).

화면에 **잔여 횟수와 초기화 시점을 함께** 보여 준다. 언제 다시 채워지는지 모르면 희소성이 아니라 그냥 막힘이다. 상한에 닿았을 때 문구는 **차단이 아니라 완결**로 쓴다 — 오늘 할 일을 끝냈다는 쪽.

> ⚠️ **화면만 만들면 우회된다.** 판정이 브라우저에서 돌기 때문에 API를 직접 부르면 6번째가 들어간다. **서버 강제는 R-6이고 M3다.** 그 사이에 실제 환자를 태우지 않는다 — 그것이 M3가 있는 이유다. **이 사실을 코드 주석에 남긴다.**

### G-7 · 프로필 축소 (C-3)

`Doctor`의 `bio` · `consultStyle` · `career`가 **제57조3항 심의 예외 목록 밖**이다.

| 허용 | 금지 |
| --- | --- |
| 의료기관 명칭 · 소재지 · 전화번호 · 진료과목 · 성명 · 면허종류 | 그 밖의 자유 서술 · 가격 · 홍보 문구 · 평점 · 후기 |

`src/domain/types.ts`를 만진다. **타입은 파일 끝에 덧붙이고 기존 타입을 재배치하지 마라** — 재배치하면 diff가 커져 검토가 안 된다.

**필드를 지우면 그것을 읽던 화면이 깨진다.** 어디서 읽는지 먼저 찾고, 화면과 픽스처(`demoDoctors.ts`)를 함께 고친다.

## 하지 말 것

- **정렬을 더하지 마라.** 지금 `/doctor/inbox`는 응급 우선 하나뿐이고 `/doctor/stories`는 응급 우선 → 원래 순서 → 보류 맨 아래다. 키워드는 매칭에만 쓰이고 정렬을 바꾸지 않는다 (C-2)
- 환자에게 의사를 골라 주는 방향을 만들지 마라. 매칭은 **사연 → 의사 인박스** 한 방향뿐이다
- 비공개 덧붙임을 만들지 마라 — G-5이고 I5다
- `BottomNav.tsx`·`App.tsx`를 만지지 마라
- 답변 문구에 진단명을 넣지 마라 (C-5)

## 확인

브라우저로 본다. **의사 화면에 들어가려면 `/expert`를 거친다.**

- 진료를 시작하고 **마쳤을 때 홈에서 사라지는가** — G-10의 핵심
- 거절했을 때 환자 쪽 상태가 어떻게 보이는가
- 잔여 횟수가 5에서 줄어드는가. **0이 됐을 때 문구가 차단조인가 완결조인가**
- 의사 프로필에서 자유 서술이 사라졌는가

## 끝났다고 판단하는 기준

1. 상태 전이 5개가 전부 동작한다. **진료를 마치면 홈에서 사라진다**
2. `encounterTrack.test.ts`가 새 전이를 덮는다
3. 의사 화면 플로우 테스트를 새로 더했다
4. 답변 상한 값이 `src/data/rules/`에 `asOf`와 함께 있고 코드에 상수가 없다
5. R-6 주석이 상한 판정 자리에 있다
6. `Doctor`에 제57조3항 예외 밖 필드가 없다. **`50-nonfunctional.md`의 C-3 행을 갱신한다**
7. `npm run test:run` 통과
