# I5 · 비공개 덧붙임 (M1-D)

새 세션에 이 파일을 통째로 주고 실행시킨다.

> **선행 조건** — I0의 **M0-5 적용 필수**(`private_threads` · `private_messages` · `expression_filter_hits` 표가 있어야 한다). Q-7은 I2의 G-4 뒤.
> **읽는 순서** — `docs/product/05-decisions.md` D-6 · `docs/product/30-feature-spec.md` §Q-5 · `docs/product/20-user-flows.md` §비공개 덧붙임 · `docs/product/40-data-model.md`의 세 표

## 이 구간이 하는 일

D-6이 정한 **구조 강제**를 화면으로 만든다. 이것이 M1의 마지막이고, 시간이 모자라면 M2로 미루는 것이 이것이다 — 네 구간 중 유일하게 다른 구간을 막지 않는다.

| # | 항목 |
| --- | --- |
| **G-5** | `/questions/:id`에 **비공개** 덧붙임. 지금 `question_notes`는 **공개** 덧붙임이고 둘은 다른 것이다 |
| **G-8** | 처방·진단·검사 지시 표현 입력 필터(PT-1~PT-5) + 걸린 기록 |
| 딸림 | `src/data/rules/privateThreadRules.ts` 신설 · Q-7(`/news`에 `비공개 회신` 태그) · Q-9(`/doctor/home`에 대기 건수) |

## G-5와 G-8을 나누지 마라

**G-5만 넣으면 경계 없는 1:1 비공개 채널이 열린다.** D-6이 「문구가 아니라 구조로 강제한다」고 정한 자리가 정확히 여기이고, **필터 없는 비공개 대화는 D-6이 막으려던 그 상태**다.

## 구조 강제 6항목 — 전부 화면이 막아야 한다

| # | 강제 | 어디가 막나 |
| --- | --- | --- |
| 1 | 환자가 먼저 말 걸어야 열린다 | RLS + 화면 |
| 2 | **답변한** 의사에게만 열린다 | RLS (`answers`와의 관계) |
| 3 | **3왕복** · 환자 500자 / 의사 400자 | 규칙 파일 + 화면 |
| 4 | 매 회신에 고정 고지. **의사가 못 지운다** | 화면 |
| 5 | 처방·진단·검사 지시 표현 필터 + 로그 | 규칙 파일 + 화면 |
| 6 | 「진료가 필요합니다」 전환 상시 노출 | 화면 |

**의사 쪽 길이(400자)가 짧은 것은 의도한 비대칭이다** — 위법 주체와 양벌규정이 향하는 곳이다. **고정 고지는 상한에 넣지 마라** — 의사가 못 지우는 글이 의사의 글자 수를 먹으면 고지를 짧게 만들자는 압력이 생긴다.

## 필터 (G-8)

**진단명 사전을 만들지 마라.** 단정 어미와 지시 어미를 잡는다.

```
막힌다:   「내시경 받으세요」        「위염입니다」
통과한다: 「내시경으로 봐야 하는 경우가 많습니다」
```

**막는 것은 지시이지 지식이 아니다.** 약품명은 기존 `medicationRules.ts`를 **재사용한다** — 새로 만들지 마라.

걸리면 **전송을 막고** 걸린 조각을 그 자리에 표시한다. 로그는 **규칙 ID와 조각(20자)만** 남기고 **본문은 남기지 않는다** — 막으려고 만든 장치가 새 민감정보 보관소가 되면 안 된다.

## 값을 코드에 박지 마라

3왕복 · 500/400자 · PT-1~PT-5 전부 `src/data/rules/privateThreadRules.ts`에 **`asOf`와 함께** 둔다. **경계의 위치는 유권해석 대상이라 움직인다**(D-6 §남은 확인). 회신이 오면 이 파일만 고친다.

`src/domain/`은 순수해야 한다 — 무인자 `Date.now()`를 두지 마라(원칙 8).

## 명세가 없는 곳 하나

**의사 쪽 회신 입력 칸의 명세가 `30-feature-spec.md`에 아직 없다.** 시작할 때 그 절을 **먼저 채운다.** 코드부터 쓰지 마라.

## 하지 말 것

- 사진 첨부를 만들지 마라. **범위 밖이다** — 사진이 오가면 그건 원격 진찰이고 D-6부터 고쳐야 한다
- 대화 만료 기간을 만들지 마라. **상한을 다 쓰면 그 자체가 닫힘이다**
- 의사가 먼저 말 거는 경로를 만들지 마라
- 답변하지 않은 의사에게 비공개 경로를 열지 마라
- 실시간 구독을 붙이지 마라 — 지금 설계는 화면을 다시 열 때 확인하는 것이고, 알림 자리는 Q-7이다

## 확인

브라우저로 본다. 환자와 의사 두 정체성을 오가야 하므로 `/expert`를 쓴다.

- 의사가 답변하기 **전에** 비공개 경로가 안 보이는가
- 환자가 3왕복을 다 쓰면 어떻게 되는가. **닫힘이 차단조가 아니라 완결조인가**
- 「내시경 받으세요」가 막히고 「내시경으로 봐야 하는 경우가 많습니다」가 통과하는가
- 고정 고지가 의사 회신마다 붙고 지워지지 않는가
- 걸린 로그에 **본문이 안 들어가는가**

## 끝났다고 판단하는 기준

1. 강제 6항목이 전부 동작한다
2. `privateThreadRules.ts`에 `asOf`가 있고 값이 코드에 없다
3. 필터가 지시는 막고 지식은 통과시킨다 — **경계 문구로 테스트를 쓴다**
4. 로그에 본문이 없다
5. Q-7·Q-9가 붙었다
6. `30-feature-spec.md`의 의사 회신 입력 칸 절이 채워졌다
7. `npm run test:run` 통과 + 필터·왕복 상한 테스트 신규
8. **R-6이 아직 열려 있다는 주석**이 판정 자리에 있다 — 서버 강제는 M3다
