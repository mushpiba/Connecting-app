## 배경

Supabase에 8개 테이블이 있고 전 테이블에 RLS가 걸려 있다. `docs/product/40-data-model.md`가 이를 문서화하면서 **결함 5개(F-1~F-5)를 이미 식별해 뒀다.** 그 사이 `05-decisions.md`가 제품의 축을 Q&A로 바꿨고, D-6(비공개 덧붙임)과 `/care`(재진) 화면이 새 데이터를 요구한다.

**당신이 할 일은 스키마를 갈아엎는 것이 아니라, 화면이 요구하는 것을 최소한으로 더하고 이미 식별된 결함을 닫는 것이다.**

### 2. D-6 — 비공개 덧붙임

D-6은 닫혔지만 **경계의 위치는 유권해석 대상이라 움직일 수 있다.** 스키마는 이 결정이 뒤집혀도 **마이그레이션 없이** 비공개를 끄거나 넓힐 수 있어야 한다.

구조 강제 6항목 중 스키마가 받쳐야 하는 것:

| 항목 | 스키마 요구 |
| --- | --- |
| 환자가 먼저 말 걸어야 열린다 | 최초 발화자를 알 수 있어야 한다 |
| 답변한 의사에게만 열린다 | `answers`와의 관계로 강제. **RLS로** |
| 왕복 횟수 상한 | 스레드별 카운트 조회가 싸야 한다 |
| 경계 이탈 표현 필터 | 걸린 기록을 보관한다 — 양벌규정 방어 자료 |

- 기존 `question_notes`(migration-002)를 확장할 수 있는지 먼저 본다. 새 테이블은 그다음이다
- RLS로 "환자 본인과 답변한 의사만"을 강제한다. **화면이 아니라 서버가 막아야 한다**
- 민감정보(개인정보보호법 제23조)다. 보존 기간과 파기 정책을 문서에 적는다

### 3. `/care` — 재진의 두 출처 (Q-4 닫힘)

- **앱 내 이력** — 기존 `bookings`·`encounters` 조회. 새 테이블이 필요 없다
- **환자 직접 등록** — 검증되지 않은 의료기관 데이터가 들어온다. 이쪽은 설계가 필요하다 (Q-6)

Q-6에서 정할 것:

- 직접 등록한 곳을 `clinics`에 넣는가, 별도 테이블에 두는가. **`clinics`에 섞으면 검증된 데이터가 오염된다**
- 나중에 실제 `clinics` 레코드와 같은 곳으로 판명되면 어떻게 잇나
- 신뢰 등급을 컬럼으로 갖는다. 화면이 두 출처를 구분해 표시해야 하므로 조회 결과에 등급이 실려야 한다
- 직접 등록한 의료기관 정보는 **다른 환자에게 보이지 않는다.** 본인만 본다 — RLS로 강제

### 4. C-4 — 기록의 주체는 의료인이다

앰비언트 기록 초안은 **의사가 확정하기 전에는 진료기록으로 저장하지 않는다.** 임시 자료와 진료기록을 스키마에서 분리하고, 어느 쪽인지 컬럼으로 구분되게 한다. `00-product-definition.md`가 이미 원칙으로 갖고 있다.

### 5. 규칙은 DB가 아니라 데이터 파일에 둔다

`src/data/rules/*`에 `asOf`와 함께 있는 것들(비대면 자격 파라미터, 문진 규칙, 응급 신호)은 **DB로 옮기지 않는다.** 법령이 바뀌면 파일만 고치는 구조가 원칙 7이다. 스키마에 `revisit_valid_months` 같은 컬럼을 만들지 않는다.

## 각 테이블을 적는 형식

```markdown
### `테이블명`

**무엇을 담나** — 한 문장.
**누가 읽고 쓰나** — RLS 정책을 사람 말로. 정책 이름도 함께.

| 컬럼 | 타입 | 널 | 기본값 | 무엇 | 읽는 화면 |
| --- | --- | --- | --- | --- | --- |

**읽는 화면이 비어 있는 컬럼은 F-2가 된다.** 지우거나, 언제 쓸지 적는다.

**인덱스** — 어느 조회를 위한 것인지.
**Realtime** — 발행하는가. 누가 구독하는가.
```

## 하지 말 것

- 기존 마이그레이션 파일을 수정하지 말 것. 이미 적용됐다
- 코드를 고치지 말 것. 스키마 초안까지가 범위다
- 화면이 요구하지 않는 컬럼을 만들지 말 것. "나중에 쓸 것 같아서"가 F-2를 만들었다
- 규칙 파라미터를 DB로 옮기지 말 것
- D-6·Q-4가 안 닫혔으면 임의로 정하지 말 것. **막히면 물어본다**

## 끝났다고 판단하는 기준

1. F-1~F-5가 전부 "닫힘" 또는 "이유를 적은 보류"다
2. 모든 컬럼에 읽는 화면이 적혀 있거나, 없으면 그렇다고 표시돼 있다
3. 모든 RLS 정책이 사람 말로 적혀 있고, 실제 `supabase/*.sql`의 정책 이름과 일치한다
4. 비공개 덧붙임을 끄고 켜는 데 마이그레이션이 필요 없다
5. `src/data/rules/*`의 파라미터가 스키마에 들어가지 않았다
6. 문서의 모든 테이블·컬럼이 실제 SQL과 대조돼 있다
