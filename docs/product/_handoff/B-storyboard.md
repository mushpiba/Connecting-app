## 화면 하나를 적는 형식 — 전부 이 형식으로

```markdown
### `/라우트` · 화면 이름

**누구의 무엇을 해결하나** — 페르소나 ID와 실패 조건. 못 적으면 이 화면은 만들지 않는다.

**왜 이렇게 생겼나** — 이 배치를 택한 이유. 다른 앱이 그렇게 해서가 아니라 우리 도메인의 이유로.

| 상태 | 화면 | 다음 |
| --- | --- | --- |
| 비어 있음 | | |
| 불러오는 중 | | |
| 정상 | | |
| 오류 | | |
| 권한 없음 | | |

**동작** — 누를 수 있는 것과 각각의 결과. 되돌릴 수 없는 것은 표시한다.
**문구** — 화면에 실제로 나가는 한국어. "적절한 안내 문구" 같은 자리표시자 금지.
**제약** — 입력 칸 수 / 한 화면의 목적 수 / 첫 피드백까지의 시간.
**금지** — 이 화면에 두면 안 되는 것과 그 근거 ID(C-1~C-5).
```

### 형식에 대해

**레이아웃이 아니라 근거를 적는다.** 참고한 UX 글의 요지가 이것이다 — *"화면 구성(HOW)이 아니라 왜(WHY) 그런 선택을 했는가를 역설계해야 한다. 단순함은 결과이지 원인이 아니다. 도메인이 다르면 심리도 다르다."*

**근거를 못 적는 화면은 아직 설계된 게 아니다.** 그런 화면은 목록에 남기고 "근거 미정"이라고 쓴다. 그럴듯한 이유를 지어내지 않는다.

## 반드시 다룰 것

### 1. 다섯 가지 상태를 전부 적는다

특히 **비어 있음**. 무료 커뮤니티는 초기에 사연도 답변도 없다. 빈 화면이 곧 첫인상이다.

### 2. `05-decisions.md` P-1을 적용한다

| 줄인다 | 늘린다 |
| --- | --- |
| 입력 칸 수 · 한 화면의 목적 수 · 결정 횟수 | 진행 상태 · 근거 · 다음에 일어날 일 |

힉의 법칙을 이 도메인에 그대로 적용하지 않는다. 아픈 사람에게 정보를 줄이면 불안이 는다.

### 3. 신설·변경 화면을 우선한다

`15-information-architecture.md` §3에서 `신설`·`변경`으로 표시된 것들이다. 최소한 이것들:

- `/home` — 사연 피드 + 진행 상태 스트립 (역할 변경)
- `/care` — 지도 + 재진(두 출처) + 예정된 예약 (신설, IA-1의 두 번째 진입로 전체)
- `/news` — 탭 승격
- `/questions/:id` — 비공개 덧붙임. **D-6 구조 강제 6항목을 화면으로 옮긴다**
- `/doctor/inbox` — 잔여 답변 횟수(5회/일)와 초기화 시점 상시 노출
- `/doctors/:doctorId` — C-3에 맞춘 프로필 필드 축소

### 6. 이 문서에서 정해야 하는 수치 (Q-5)

`05-decisions.md` D-6의 구조 강제 항목 3·5는 수치가 비어 있다. 여기서 정한다.

- 비공개 덧붙임의 **왕복 횟수 상한**과 **1회 길이 상한**
- **처방·진단·검사 지시로 읽히는 표현**의 목록과 걸렸을 때의 동작

정한 값은 `src/data/rules/*`에 `asOf`와 함께 두도록 명세한다 (원칙 7). 스키마나 코드에 상수로 박지 않는다.

### 4. C-2를 화면 단위로 못 박는다

의사가 보이는 모든 화면에 적는다 — 정렬 기준은 무엇이고, 그 기준이 공개되는가. **"추천"이라는 말이 화면에 등장하면 실패다.**

`/questions/:id`에서 답변 → 의사 프로필 → 예약으로 가는 **한 단계 경유**를 명시한다. 이 단계는 마찰이 아니라 분리의 증거이므로 없애지 않는다.

### 5. 문구를 실제로 쓴다

`00-product-definition.md` 원칙 6 — 동의 문구는 실제로 일어나는 일과 같아야 한다. 데이터가 서버로 가는데 브라우저에만 둔다고 적으면 그건 오타가 아니라 **동의를 잘못 받은 것**이다. 문구를 적을 때 코드에서 실제 동작을 확인한다.

## 끝났다고 판단하는 기준

1. 라우트 인벤토리가 `src/App.tsx`와 정확히 일치한다 (개수까지)
2. 모든 화면에 다섯 상태가 적혀 있다 — 해당 없으면 "해당 없음"이라고 명시
3. 모든 화면에 "왜 이렇게 생겼나"가 있고, 근거가 우리 도메인의 이유다
4. 자리표시자 문구가 하나도 없다
5. 의사가 보이는 화면마다 정렬 기준과 C-2 판정이 있다
6. `git diff --stat`이 `30-feature-spec.md` 하나만 보여 준다
