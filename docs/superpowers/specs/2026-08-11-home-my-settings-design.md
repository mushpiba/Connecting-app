# MediVU 홈·MY 설정 데모 설계

## 목표

- 하단 내비게이션은 `홈 · 사연 · Q · 내소식 · MY`를 유지한다.
- 중앙 Q는 현재 3단계 질문 작성 화면을 연다.
- 내소식은 종 아이콘을 사용하고 내 사연과 그 사연에 달린 의사 답변만 보여준다.
- 홈에서는 다른 사용자의 HOT·공감 글을 제거하고, 현재 사용자의 다음 행동을 안내한다.
- MY의 비대면 진료 사전 확인은 요약 버튼으로 유지하고 별도 화면에서 기존 양식을 연다.
- 주소·결제수단·알림·개인정보 설정을 조작 가능한 데모 상세 화면으로 제공한다.

## 홈 정보 구조

홈은 커뮤니티 피드가 아니라 개인 대시보드로 구성한다.

1. `어디가 불편하신가요` 질문 CTA
2. 비대면 사전 확인과 받은 답변 요약
3. 최신 내 활동 1건: 내 사연 또는 도착한 답변을 최신순으로 표시
4. 빠른 메뉴: 진료 사전 확인, 예약 내역, 내소식
5. 진료 준비 안내: 증상 시작일, 복용 중인 약, 궁금한 점을 미리 정리하도록 안내
6. `사연 둘러보기` 진입 카드: 게시물을 홈에 노출하지 않고 사연 탭으로만 연결
7. 설치 가능한 환경에서만 PWA 설치 안내

공개 사연과 공감 정렬은 `/stories`에서만 제공한다.

## MY 정보 구조

MY의 상단 프로필과 내 사연·받은 답변 수는 유지한다. 메뉴는 다음 두 그룹으로 나눈다.

### 진료 준비

- 비대면 진료 사전 확인 → `/me/precheck`
- 주소 설정 → `/me/address`
- 결제수단 설정 → `/me/payment`
- 예약 내역 → `/me/appointments`

### 앱 설정

- 알림 설정 → `/me/notifications`
- 개인정보·공개범위 → `/me/privacy`
- 앱 사용법 다시 보기 → `/onboarding`
- 데모 초기화

## 데모 설정 화면

설정값은 React 메모리에만 유지하며 새로고침하면 초기값으로 돌아간다. 실제 주소 검증, 카드 등록, 결제, 푸시 권한 요청, 개인정보 처리 동의는 수행하지 않는다.

- 주소: 기본 지역과 상세 주소 별칭을 입력하고 저장 완료 안내를 보여준다.
- 결제수단: 가상 마스킹 카드 중 하나를 선택한다. 카드번호·CVC를 입력받지 않는다.
- 알림: 답변 도착, 예약 안내, 서비스 소식 토글을 제공한다.
- 개인정보: 기본 질문 공개 범위와 프로필 표시 여부를 선택한다. 이번 범위에서는 기존 질문 작성 로직의 공개 범위를 강제로 바꾸지 않는다.
- 예약 내역: 기존 데모 예약 상태에서 현재 환자의 예약을 읽어 목록으로 표시한다.

## 상태와 컴포넌트

- `CommunityContext`의 기존 질문·답변·예약·의료 판정 인터페이스는 변경하지 않는다.
- 설정 데모 상태는 앱 범위의 `PatientSettingsContext`로 분리해 MY 상세 경로 사이에서 유지한다.
- 홈 최신 활동은 기존 `buildMyActivity`를 재사용한다.
- 설정 상세 화면은 공통 헤더·저장 버튼·데모 안내 리듬을 공유하되 과도한 범용 컴포넌트는 만들지 않는다.

## 테스트

- 중앙 Q와 내소식 탭 경로·아이콘을 검사한다.
- 홈에 HOT 사연이 없고 최신 활동, 빠른 메뉴, 사연 진입 CTA가 보이는지 검사한다.
- MY 메뉴에서 각 설정 상세 화면으로 이동하는지 검사한다.
- 주소·결제·알림·개인정보 설정의 세션 내 변경과 완료 안내를 검사한다.
- 예약 내역이 기존 예약 상태에서 파생되는지 검사한다.
- 전체 회귀 테스트와 PWA 빌드를 수행한다.

## 배포

검증 후 기능 브랜치를 배포 대상 `main`에 통합하고 원격에 푸시한다. GitHub Pages 워크플로가 성공하면 설치형 Chrome 앱은 서비스워커의 새 버전을 감지하며, 앱을 다시 열거나 새로고침하면 갱신된다.
