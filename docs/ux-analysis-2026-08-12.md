# MediVU UX 분석 — 첫 사용자 관점

- **일자**: 2026-08-12
- **대상**: `http://localhost:4174/medi-commu/index.html` (로컬 데모 빌드)
- **방법**: 코드 수정 없이 브라우저로 환자/의사 양쪽 전 기능 실사용 탐색
- **목표 기준**: 토스·카카오톡급의 "처음 써도 편하고, 계속 쓰고 싶은" UX

## 총평

뼈대 좋음. 온보딩 3단계, "어디가 불편하신가요" 첫 화면, 증상 구조화 폼, 정책 투명성(비대면 가능/불가 사유 설명), 동의 화면, 진료기록 초안 — 방향 전부 맞음.

문제는 **마감**: 피드백 부재, 데이터 유실, 완료 순간의 감정 설계 없음. 토스가 이긴 지점이 바로 이 마감임.

## 🔴 기능 버그 (UX 이전 문제 — 신뢰 직결)

### 1. 비대면 신청 유실
환자가 한빛이비인후과 병원 페이지에서 "비대면 진료 신청" 탭 → 버튼만 "신청함"으로 회색 변함.

- 의사 진료 탭 "받은 비대면 진료 신청" 목록에 안 뜸 (기존 Test123123 건만 존재)
- 환자 홈 · 내소식 · 예약 내역 어디에도 흔적 없음
- **신청이 허공으로 사라짐**

### 2. 대면 예약 희망 시간 유실
예약 3단계 끝 "희망 시간 전달" 클릭 → 화면 무반응. 예약 내역 여전히 "전달한 희망 시간이 없어요". 성공/실패 피드백 0.

### 3. 날짜 계산 오류 2건
- **예약 날짜 선택**: 오늘 8/12인데 9·10·11일(과거)이 선택 가능하고 기본값이 월 10일. 과거 날짜로 예약 완주됨.
- **사연 상세 "기간"**: 8/9 시작 입력 → "1일째" 표기 (실제 4일째).

### 4. 진료과 분류 실패
"목이 아프고 침 삼킬 때 따가워요" 입력 → "진료과를 좁히지 못했습니다, 가정의학과 먼저" 응답.

- 인후통은 이비인후과 매핑의 가장 기본 케이스. 키워드 사전 보강 필요.
- 진료실 "통화에서 나온 키워드"도 목·침 못 뽑음 (빈 패널).

### 5. 통화 종료 후 받아쓰기 계속 "듣는 중"
통화 끝나도 마이크 청취 유지. 의료 앱에서 마이크는 민감 — 통화 종료 시 자동 중지해야.

### 6. 딥링크 역할 불일치
expert 모드 상태에서 `#/home` 진입 → 환자 홈 콘텐츠 + 의사 하단탭 혼합 렌더.
(환자/의사 통합은 테스트용 의도라 해도, 데모 시연 중 헷갈림 유발.)

## 🟡 토스/카톡급으로 가기 위한 UX 격차 (우선순위순)

### 1. "완료의 순간"이 전부 무음
- 질문 등록 → 회색 글씨 한 줄 ("브라우저 메모리에만 저장했습니다")
- 비대면 신청 → 버튼 회색화가 끝
- 토스 공식: 큰 체크 애니메이션 + "질문이 올라갔어요" + **다음에 일어날 일** ("의사 답변이 오면 알려드릴게요, 보통 하루 안에 와요")
- 의료는 불안한 상태로 오는 앱 → 이 안심 멘트가 곧 리텐션

### 2. 신청/예약 후 상태 추적 화면 부재
택배 추적처럼: 신청됨 → 병원 확인 중 → 진료방 열림.
지금은 신청 후 환자가 볼 곳이 없음 (위 버그와 겹침). "환자를 통해 방까지" 흐름의 마지막 조각.

### 3. 검증 UX가 브라우저 기본 툴팁
"이 입력란을 작성하세요" 오렌지 말풍선 = 시스템 이질감.
인라인 메시지 + 해당 필드로 스크롤 + 가벼운 흔들림으로 교체.

### 4. 증상 폼 1단계가 너무 김
한 화면에 질문 9개. 토스식은 **한 화면 한 질문** (제목 → 증상 → 언제부터 → 어디가 → …).

- 아픈 사람·고령자는 긴 스크롤 폼에서 이탈
- 현 구조 유지 시에도: 필수(제목/내용/날짜)와 선택(약/알레르기/NRS) 시각 분리, 선택 항목은 접어두기

### 5. 불가역 규칙이 마지막에 갑자기 등장 + 미리보기에 내용 요약 없음
- "올린 뒤에는 고칠 수 없습니다"는 작성 시작 전에 알려야
- 미리보기 화면인데 내가 쓴 내용 요약이 없음 — "정리한 내용을 확인하세요"라면서 분류 결과만 표시
- 제목/증상/공개범위 요약 카드 필수

### 6. 용어·표기 불일치
| 위치 | 문제 |
| --- | --- |
| 우상단 토글 | "환자 화면" ↔ "**expert**" (영어 노출, 첫 사용자 의미 모름) |
| 게시판 | 탭은 "사연", 상세 URL은 `questions`, 홈에선 "질문" |
| 진료방 | 방 이름 생 UUID 노출 (`demo-001d67c8-…`) |
| 의사 MY | 계정 이름이 "검증환자" |

### 7. 공감·답변 상호작용 약함
리스트에 공감 수 있는데 상세에서 공감 버튼 없음.
지식인류 핵심 루프 = "나도 같은 증상이에요" 공감 → 같은 증상자 모임 → 의사 답변 가치 증폭. 게시판 성장 엔진이라 초기부터 필요.

## 💬 "정보량 많으면 불편 — 의료에도 적용되나"

적용됨. 단, 방식이 다름:

- **소비 앱**: 정보 삭제가 답
- **의료 앱**: 정보는 필요하되 **시점 분산**이 답
  - 병원급 예외 규칙, 판정 기준일, 면책 문구 — 다 필요한 정보지만 지금은 한 화면에 쏟아냄 (인하늘병원 안내 카드: 문단 5개 벽)
  - 원칙: **결론 먼저 한 줄** ("이 병원은 비대면이 안 돼요 → 대면으로 안내할게요") + "왜인지 보기" 접기
  - 법적 고지는 스크롤 하단·동의 화면에 모으기
- 반대로 **신뢰 정보는 의료에서 더 보여야 함**: 의사 경력·답변 수·응답 시간. 지금 의사 프로필이 한 줄 소개뿐. 정보량 줄이기의 예외 지점.

문구 톤은 이미 좋음 ("~해 드립니다" 존댓말 안내). 구조만 "결론 → 상세 접기"로 바꾸면 됨.

## ✅ 잘한 것 (유지)

- 진료실 입장 전 동의 화면 + STT 한계 고지 (브라우저 STT가 음성을 외부로 보낸다는 정직한 안내)
- 받아쓰기 실패 시 타이핑 폴백 + 진료기록 초안 자동 생성 + 초안 복사
- 예약 시 서류(진료확인서/영수증/세부내역서) 미리 요청 — 실사용자 페인포인트 정확
- 비대면 불가 사유를 규칙 기반으로 설명 + "최종 판단은 의료진" 명시
- 공개 범위 3단계 선택 (공개 / 과 한정 / 내 주치의만)
- 점심시간 제외 안내, 야간 슬롯 경고 등 디테일

4. **분류 키워드 사전 보강** (인후통 → 이비인후과부터)
